1. Project Overview

This project performs Big Data Analytics on network intrusion detection data using the UNSW-NB15 dataset — a well-known cybersecurity benchmark created by the University of New South Wales. The analysis leverages the Apache Hadoop ecosystem, specifically Apache Hive running on YARN / MapReduce, to query millions of network flow records and uncover patterns in attack traffic.

Goal: Analyze destination addresses targeted by attacks, network flow characteristics (duration, bytes), temporal attack patterns (hourly), and protocol/service vulnerabilities using distributed SQL queries in Apache Hive.

2. The UNSW-NB15 Dataset

The UNSW-NB15 dataset was generated by the Cyber Range Lab of the Australian Centre for Cyber Security (ACCS). It contains a hybrid of real modern normal activities and synthetic contemporary attack behaviours, captured using the IXIA PerfectStorm tool.

6. Hive Query Deep Dive

🎯

Query 1: Destination Address Analysis

File: destination_address_analysis.sql

Identifies the Top 15 destination IP addresses most targeted by attacks. For each destination, it calculates:

  • Total records, attack records, normal records
  • Attack percentage within that destination
  • Number of distinct attack categories
  • Dominant attack category (most frequent) and its share

Query Logic Flow

CTE:
destination_summary
GROUP BY dstip
→
CTE:
category_counts
WHERE label=1
→
CTE:
ranked_categories
ROW_NUMBER()
→
JOIN + Filter
rank = 1
LIMIT 15

Technique: Uses 3 CTEs (Common Table Expressions) and a window function ROW_NUMBER() to find the dominant attack category per destination IP.

📊

Query 2: Flow Characteristics

File: flow_characteristics.sql

Profiles each attack category by flow duration and total bytes transferred. Reports:

  • Mean, approximate median (p50), and 95th percentile (p95) for duration
  • Mean, approximate median and p95 for total bytes (sbytes + dbytes)
  • Count and percentage of zero-duration flows (instantaneous connections)

Query Logic Flow

CTE: flow_measures
sbytes + dbytes
→
CTE: category_summary
PERCENTILE_APPROX
→
Final SELECT
ORDER BY count

Technique: Uses PERCENTILE_APPROX with accuracy parameter 10,000 for efficient approximate quantile computation on large datasets.

⏰

Query 3: Hourly Activity Analysis

File: hourly_activity_query.sql

Provides a temporal view by grouping traffic into hourly buckets per capture date:

  • Converts Unix timestamp stime → date + hour (UTC timezone)
  • Within-hour attack percentage
  • Each hour's share of its day's total attacks (window function)

Query Logic Flow

SET timezone
UTC
→
CTE: time_fields
FROM_UNIXTIME
→
CTE: hourly_summary
GROUP BY date,hr
→
Window: daily
SUM OVER date

Technique: Sets hive.local.time.zone=UTC for consistent time handling. Uses SUM() OVER (PARTITION BY date) window function for daily context.

🔌

Query 4: Protocol & Service Analysis

File: protocol_and_service_query.sql

Identifies the Top 15 protocol/service combinations most associated with attacks:

  • Groups by protocol (TCP, UDP, etc.) + service (HTTP, DNS, etc.)
  • Filters groups with at least 100 records (statistical significance)
  • Attack percentage within each group + global share of all attacks

Query Logic Flow

CTE: service_summary
GROUP BY proto,svc
→
Window: total atk
SUM OVER ()
→
Filter ≥ 100
LIMIT 15

Technique: Uses SUM() OVER () (unbounded window) to compute global attack total, enabling per-group share calculation without a self-join.

9. How to Run the Project

Prerequisites

This project requires a Linux environment with a fully configured Hadoop ecosystem. It cannot run directly on Windows without WSL or a VM.

  1. ✅ Linux VM or WSL (Ubuntu recommended)
  2. ✅ Java 8 (OpenJDK 1.8.x) installed and JAVA_HOME set
  3. ✅ Hadoop 3.x installed and configured (HDFS + YARN)
  4. ✅ Apache Hive 3.x installed with metastore configured
  5. ✅ HDFS running with NameNode and DataNode active
  6. ✅ YARN running with ResourceManager and NodeManager active

Step-by-Step Execution

Step 1: Start Hadoop Services

# Start HDFS start-dfs.sh # Start YARN start-yarn.sh # Verify services are running jps # Expected: NameNode, DataNode, ResourceManager, NodeManager, SecondaryNameNode

Step 2: Download the Dataset

# Download the main dataset wget -O UNSW-NB15.csv "https://www.dropbox.com/s/4xqg32ih9xoh5jq/UNSW-NB15.csv?dl=1" # Download feature definitions wget -O UNSW-NB15_features.csv "https://www.dropbox.com/s/c8qrzd99z5s9ub6/UNSW-NB15_features.csv?dl=1"

Step 3: Prepare the Dataset (⚠️ Script Missing)

⛔ BLOCKER: The preparation script that transforms UNSW-NB15.csv into UNSW-NB15_prepared.csv is not included in the repository. You must write your own or contact the project author. The prepared CSV must have proper headers matching the schema columns.

Step 4: Upload to HDFS

# Create HDFS directory hdfs dfs -mkdir -p /user/hive/warehouse/YOUR_DATABASE.db/network_flows_analysis # Upload the prepared CSV hdfs dfs -put UNSW-NB15_prepared.csv /user/hive/warehouse/YOUR_DATABASE.db/network_flows_analysis/

Step 5: Create the Hive Table (⚠️ DDL Missing)

⛔ BLOCKER: hive_table_definitions.sql is empty. You need to create the table yourself. Here's a suggested DDL based on the inferred schema:
CREATE DATABASE IF NOT EXISTS YOUR_DATABASE; USE YOUR_DATABASE; CREATE EXTERNAL TABLE IF NOT EXISTS network_flows_analysis ( dstip STRING, label INT, attack_cat STRING, dur DOUBLE, sbytes BIGINT, dbytes BIGINT, stime BIGINT, proto STRING, service STRING -- ... add other columns from the full 49-column schema as needed ) ROW FORMAT DELIMITED FIELDS TERMINATED BY ',' STORED AS TEXTFILE LOCATION '/user/hive/warehouse/YOUR_DATABASE.db/network_flows_analysis' TBLPROPERTIES ('skip.header.line.count'='1');

Step 6: Run the Analysis Queries

# Run each query independently hive --database YOUR_DATABASE -f apache_hive_approach/destination_address_analysis.sql hive --database YOUR_DATABASE -f apache_hive_approach/flow_characteristics.sql hive --database YOUR_DATABASE -f apache_hive_approach/hourly_activity_query.sql hive --database YOUR_DATABASE -f apache_hive_approach/protocol_and_service_query.sql

Each command launches MapReduce jobs via YARN. Expect each query to take several minutes depending on dataset size and cluster resources.

💡 Summary Verdict

The analysis queries are complete and well-written, using proper CTEs, window functions, and approximate percentile computations. However, the project is not self-contained — it is missing the table DDL and data preparation pipeline needed to actually run it. You would need to:
① Set up Hadoop + Hive on a Linux VM (or use a pre-configured environment like Cloudera/HDP sandbox),
② Download the dataset and write your own preparation script,
③ Write the CREATE TABLE statement,
④ Then the 4 analysis queries will work.
